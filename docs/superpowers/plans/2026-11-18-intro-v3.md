# 시작 화면 v3 + 지도 디자인 언어 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 시작 화면(`/`)을 v3 디자인(상단 바·히어로·세 칸 목록·카카오맵·유튜버 고르기)으로 새로 만들고, 지도 화면의 색·글꼴·로고·핀을 v3 에 맞춘다.

**Architecture:** 새 API `/api/intro` 가 유튜버 10명 분 예시 식당(유튜버당 2곳, 검증된 대표 댓글)과 숫자를 한 번에 내려 주고, `public/start.js` 가 고른 유튜버로 걸러 세 칸과 카카오맵을 그린다. 지도 화면은 `public/map.html` 의 CSS 토큰·글꼴·로고 마크업만 바꾼다.

**Tech Stack:** Next.js route handler + `pg`, 정적 HTML/JS, 카카오맵 JS SDK, Playwright 점검 스크립트, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-18-intro-v3-design.md`

## Global Constraints

- 색: Orange `#F2622A` · Orange soft `#FEEDE5` · Surface `#F8F6F3` · Ink `#1F1B18` · 반응 `#17806B` · 쓴소리 `#D9392B` · Sea `#B7DBEE` · 바탕 순백. 오렌지는 선택·핵심 숫자에만.
- 글꼴: `Noto Sans KR`(300·400·500·700·900) + `IBM Plex Mono`(500·600). 숫자·통계는 모노.
- 화면 문구는 이것만: 로고 "르슐랭 가이드" · "맛집 지도 보러가기 →" · 라벨 "유튜버 × 방문 후기 × 지도" · 제목 "좋아하는 유튜버가 간 식당, / 다녀왔다고 적은 사람들은 / 뭐라고 했을까?" · "건의 방문 후기" · "영상에서 봤다" "다녀왔다고 적은 사람들" "지도에서 찾는다" · "내 유튜버를 고르세요" · "즐겨찾기 N / 3" · "내 유튜버 맛집 지도 열기 →" · "좋았다는 이야기" "아쉬웠다는 이야기" · 숫자 단위(편·건·곳·식당·영상·댓글·반응·쓴소리·좋아요·조회)·배지 이름. **설명 문장 금지.** "방문 인증"·점수·순위 표현 금지.
- 화면 숫자는 전부 API 값. HTML/JS 에 데이터 숫자 리터럴 금지(3명 한도·UI 치수는 예외).
- 유튜버 고르기 동작 유지: `lesulin.fav`(id 배열, 최대 3) · 4번째면 가장 먼저 고른 사람 빠짐 · 다시 누르면 해제 · 데이터 오기 전/실패 시 저장값 보존 · 링크로 나가도 저장 · localStorage 예외 대응.
- `/api/track` 방문 기록(view, path=`/`) 유지. 점검 스크립트는 기록을 보내지 않음(route + sendBeacon 무력화 — 기존 방식).
- 링크: 영상 → `https://www.youtube.com/watch?v=<id>` 새 탭 · 식당·핀 → `/map.html?store=<id>` · 길찾기 → `https://map.kakao.com/link/to/<이름>,<lat>,<lng>`.
- 복춘식당 예시(`/api/showcase`, 사람이 확인한 댓글 2건)는 성시경(`c1`) 목록 맨 앞에 유지.
- 커밋 끝: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. 커밋 이메일은 저장소 설정(noreply) 그대로.

### Task 1: `/api/intro`

**Files:** Create `src/lib/intro.ts`, `src/app/api/intro/route.ts`, `scripts/check-intro.mjs`

**Interfaces — Produces** `GET /api/intro` (캐시 헤더는 `/api/seed` 와 같음):
```ts
type IQuote = { text: string; likes: number; at: string; wait: boolean };
type IPlace = { id: string; name: string; region: string; category: string; lat: number; lng: number;
  used: number; neg: number; waits: number; lvl: number | null; creatorId: string; curated: boolean;
  video: { id: string; title: string; views: number; dur: string | null; at: string };
  good: IQuote | null; bad: IQuote | null };
type Intro = { meta: { stores: number; videos: number; comments: number };
  creators: { id: string; name: string; stores: number }[];   // 숨김 뺀 식당 수 많은 순
  places: IPlace[] };                                          // 유튜버마다 최대 2곳, good 은 항상 있음
```
- 후보: RATED·숨김 아님·그 유튜버 영상에 연결된 식당, `store_stats.comments_used` 많은 순.
- 검증: `store_stats.quotes.pos.x` 의 출처 댓글(그 식당 영상 댓글 중 `left(trim(body),170)` 일치)의 영상이 숨김 뺀 식당 이름 1개에만 연결되고 `creator_id <> 'c4'`. `neg` 도 같은 검증을 통과할 때만 `bad`. `wait` = 그 댓글에 `comment_aspects.aspect='대기'` 있음.
- `video` = 그 유튜버의 그 식당 영상 중 조회수 최대. `meta.comments` = `/api/seed` 메타와 같은 값.
- `c1` 은 `src/lib/showcase.ts` 의 `loadShowcase()` 결과(s126, 고정 댓글)를 `curated: true` 로 맨 앞에 두고 나머지 1곳을 채운다.
