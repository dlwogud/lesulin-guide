# 르슐랭 시작 화면 — 설계

2026-11-18 · 최종발표 11/25

## 왜

중간발표 피드백: 첫 화면 구조가 유튜브플레이스와 비슷하고, 르슐랭의 차별점(방문자 반응)이
처음부터 보이지 않는다. 지금은 `/` 에 들어가면 지도가 바로 뜨고 유튜버 고르기 창이 그 위에
겹쳐 떠서, 처음 3초의 인상이 "유튜버 맛집 지도"다.

**완료 기준** — 처음 보는 사람에게 첫 화면을 3초 보여주고 "다른 유튜버 맛집 지도와 뭐가 달라
보여?"라고 물었을 때 "다녀온 사람들의 반응도 보여준다"는 답이 나온다.

## 목표 / 하지 않을 것 / 실패로 볼 것

- 목표: 지도 앞에 지도가 보이지 않는 시작 화면을 둔다. 핵심 문장 + 실제 식당 예시 한 곳
  (영상 → 다녀왔다고 적은 댓글 → 지도에서 찾기) + 유튜버 선택(최대 3명, 건너뛰기 가능) + 지도 보기 버튼.
- 하지 않을 것: 지도 화면 리디자인, 시작 화면에 르슐랭 배지·실시간 투표 배치,
  위치 권한을 시작 조건으로 만들기.
- 실패로 볼 것: 유튜버 선택만 있는 빈 온보딩 / "방문 인증"이라는 표현 /
  방문 언급 수를 품질 점수처럼 표현 / 화면 숫자 하드코딩(평가 기준 위반) /
  자동 분류가 틀린 댓글을 예시로 노출.

## 접근 방식 (A로 결정)

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 예시가 주인공** | 문장 아래 실제 식당 한 곳을 ①영상 → ②다녀왔다고 적은 댓글 N건(좋았다/아쉬웠다) → ③지도에서 찾기로 펼치고, 유튜버 칩은 그 아래 | **선택.** 처음 눈에 들어오는 게 "N건 + 댓글"이라 3초 기준에 맞음 |
| B. 유튜버 선택이 주인공 | 왼쪽 얼굴 10개 + 버튼, 오른쪽 예시 카드 | 처음 눈에 들어오는 게 얼굴이라 "유튜버 고르는 앱"으로 읽힐 위험 |
| 지금 모달을 키우기 | 지도 위 창에 예시만 추가 | 뒤로 지도·핀이 비쳐서 첫인상이 그대로 |

시안: `.superpowers/brainstorm/…/content/start-screen.html`

## 정한 것

**경로**
- `/` = 새 시작 화면 (`public/index.html` 을 시작 화면으로 교체). 지도는 `/map.html` 그대로.
- 지도 상단 로고 → `/` 로 돌아가 유튜버를 바꿀 수 있게.
- *(내 판단)* `/` 는 다시 와도 항상 시작 화면을 보여주고, 이전에 고른 유튜버를 미리 선택해 둔다.
  발표 시연에서 늘 같은 첫 화면이 나와야 하고, "돌아와서 바꾸기"가 요구사항이라서.
- *(내 판단)* 지도에 처음 들어갈 때 유튜버 창이 자동으로 뜨던 동작은 끈다 — 시작 화면이 그 역할을 함.
  지도 왼쪽의 "내 유튜버 고르기" 버튼과 `?pick=1` 은 그대로 둔다.
- 선택 저장은 지금 쓰는 localStorage(`lesulin.fav`)를 그대로 써서 지도와 공유한다.

**예시 식당 — 사람이 고르고, 숫자는 DB에서**
- 고정: 복춘식당(`s126`), 성시경의 먹을텐데 영상 `ZZAqSGZjiPo`.
- 보여줄 댓글은 원문을 사람이 확인한 두 건을 댓글 번호로 지정:
  좋았다는 이야기 `291815`, 아쉬웠다는 이야기 `291672`.
  자동 분류의 대표 댓글은 쓰지 않는다 — 나진국밥의 "아쉬운 점"이 실제로는 칭찬이었고,
  사장님 댓글이 뽑힌 식당도 있었다.
- 고른 값은 `src/lib/showcase.ts` 한 곳에만 둔다. 숫자(다녀왔다고 적은 댓글 수, 전체 댓글 수,
  웨이팅 언급 수, 조회수, 좋아요, 날짜)와 댓글 본문은 새 API `/api/showcase` 가 DB에서 읽어 준다.
- 상단의 "유튜버 N명 · 영상 N편"과 칩의 "N곳"도 DB에서 읽는다.

**연결**
- 영상 썸네일/제목 → 유튜브 영상.
- "원문 보기" → 해당 유튜브 영상 *(댓글 고유 링크는 수집하지 않아 영상으로 연결 — 내 판단)*.
- "지도에서 보기" → `/map.html?store=s126` (지도가 이 파라미터로 상세를 바로 열도록 추가).
- "길찾기" → 지도 상세에서 쓰는 카카오맵 길찾기 링크와 같은 형식.
- *(내 판단)* 지역 선택은 시작 화면에 넣지 않는다 — 요청서에서도 선택 사항이고, 지도에 이미 지역 선택·검색이 있다.

**표현**
- "다녀왔다고 적은 댓글", "좋았다는 이야기 / 아쉬웠다는 이야기", "웨이팅을 언급한 댓글".
- "방문 인증", 점수, 순위 표현 쓰지 않음.

**모바일**
- 시작 화면은 폭 720px 이하에서 ①②③이 세로로 쌓이고, 칩은 줄바꿈, 버튼은 화면 하단 고정.

## 빌더에게 맡기는 것

- 시작 화면 마크업·스타일 세부(시안 A 기준, 사이트 색상 토큰 재사용).
- `/api/showcase` 응답 형태, 캐시(`/api/seed` 와 같은 CDN 캐시).
- 데이터 로딩 중·실패 시 표시(실패하면 예시 카드를 숨기고 문장·칩·버튼은 그대로).

## 확인 방법

Playwright, 데스크톱(1440) + 모바일(390):
시작 화면 → 유튜버 2명 선택 → 지도(고른 유튜버 식당이 위로, 주황 테두리) → 예시의 "지도에서 보기"로
복춘식당 상세 열림 → 영상 링크 → 길찾기 링크. 콘솔 오류 0. 변경 전후 화면 캡처.

## 이번 범위 밖 (발표 전 따로 필요)

- **식당 상세의 대표 댓글 오분류** — 칭찬이 "아쉬운 점"에, 사장님 댓글이 대표로 나오는 식당이 있음.
- **지도·상세 화면 모바일 대응** — 시작 화면만 모바일을 맞춰서는 "모바일에서 길찾기까지" 점검을 통과 못 함.
